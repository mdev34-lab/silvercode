Launch a subagent for complex, multistep tasks (`subagent_type` required). Not for reading a known file or searching a few files; use Read, Glob or Grep.

Review handoffs: when a unit of your own work changed files, hand it to the `review` subagent instead of reviewing your own diff (see the review-loop policy): `subagent_type: "review"` (the runtime picks the matching reviewer). Pass `background: false` to ask for the verdict before you continue: the tool waits only for a reviewer whose agent is configured with `"background": false` in opencode.json, and otherwise launches the review as a background task and notifies you when the verdict is ready. When the user asks for a code review, dispatch `review` with the requirements and the diff. No review for turns that changed no files.

Launch independent agents in one message. Subagents run in the background by default; do not poll or duplicate their work. The result is not shown to the user; summarize it. Pass `task_id` to resume a session; otherwise give a detailed prompt (write code or research only, how to verify, what to return). Do not delegate edits to files you are editing.
